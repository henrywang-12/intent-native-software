# F01 · Planner substitution becomes a product feature

**Issued:** 2026-11-01 · **Resolve by:** 2028-12-31 · **Status:** open
**Working confidence:** medium, qualitative and uncalibrated. These are editorial hypotheses, not measured probabilities or promises.

## Event

At least two independent public software projects demonstrate the same effectful workflow using models from two independent developers, without changing authorization rules, and publish reproducible acceptance tests.

## Mechanism

Model choice should become less tightly coupled to execution policy when operators demand bargaining power and reliability.

## Qualification boundary

A common API is insufficient: the demonstration must include one authorized effect, one denied action and one recovery case for both planners.

## Resolution procedure

Count projects by independent governance, not forks. Archive release versions and tests. A failed demonstration does not count. Search the named product documentation where applicable, scholarly indexes and public repositories. Save the evidence and search date. At the deadline mark true if qualifying public evidence exists, false only after a documented search finds none, and unresolved if access or interpretation prevents adjudication. Keep the original wording when updating status.

## Evidence against the mechanism

If only model adapters appear while policy and recovery must be rewritten, the prediction fails.

The event is deliberately narrower than the mechanism. Its occurrence would not establish market-wide adoption, causality or Walify's success. Forecasts share assumptions and should not be multiplied as independent probabilities.
